Email providers

What a provider needs to carry it

Any email provider can carry Agent Emailing if it does three things. This page lists what a provider must and should support, describes which kinds of provider do so today, and explains how to test one.

The provider never signs anything and is never trusted to have checked anything. It carries an attachment and delivers it unchanged.

Required

What a provider must support

  • 1. Send an attachment unchanged

    The sender chooses the attachment's media type and filename, and the bytes arrive unchanged after decoding.

    Section 11.2

  • 2. Deliver an attachment unchanged

    The receiving side can get the attachment's exact bytes, from the raw message or as an attachment download.

    Section 11.2

  • 3. Sign with DKIM aligned to the sender's domain

    Every message is DKIM-signed with the signing domain aligned to the From domain. A domain the provider manages is enough.

    Sections 6.4 and 11.2

Recommended

What a provider should support

  1. Push delivery of inbound mail: a webhook, a websocket, server-sent events, or IMAP IDLE. Polling works, but it adds delay.
  2. At-least-once delivery with a stable event identifier, so a receiver can tell a retry from a new email.
  3. Inbound authentication results: SPF, each DKIM signature with its domain and result, and DMARC with alignment. Bridged mode needs these.
  4. Threading fields on sending, or a reply operation that sets them, so people see one thread.
  5. Custom headers, at least Auto-Submitted, then the optional hint headers.
  6. A custom sending domain, so an organization can send from its own domain.
  7. Delivery status reporting for bounces and deferrals.
  8. Keeping inbound mail for at least seven days, the mailbox window.
  9. Leaving the text part unchanged, with no added footer or banner. Software that checks the human part warns when the text was changed.

Implementations

The reference implementation and its adapters

The Agent Emailing Server

TypeScript on Node.js 22, with no dependencies at run time, under the Apache License 2.0. It runs one agent's email: native and bridged modes, a built-in IMAP and SMTP provider, and adapters for Resend, AgentMail, Cloudflare Email Service and Primitive.

All 19 conformance cases pass, against its library and against a running server. Get started shows how to run it.

Each adapter is built to the provider's documentation and tested against it. Some have also carried real, signed agent email. This is where each stood on 29 October 2026.

ProviderWhere it standsWhat has been shown
AgentMail Proven live A signed request and a signed respond, each with a file, went through real AgentMail inboxes. Both files arrived with their signed digests intact, and the carrier test of section 12.3 passed.
Primitive Proven live The same round trip through real Primitive addresses, with digests intact, and the carrier test passed. Primitive accepts only three custom headers, so the hint headers were dropped, and everything still arrived whole.
Resend Sending proven Sending: the carrier test and a signed request reached a real mailbox, both passing. Receiving and delivery status were tested against Resend's documentation only.

Other implementations are welcome. Run the conformance cases against yours, then open an issue in the Common Agent Standards repository with a link to it and its results, and it will be listed here.

For builders

One adapter per provider

A bridge, or an agent's runtime, that should work with any provider puts a small adapter in front of each one. The adapter turns the provider's interface into four operations: say what the provider supports, send one email, receive inbound mail, and report a sent email's delivery status. It never changes the bytes of the envelope or of a file.

The full interface is in section 11.4 of the specification.

Test a provider

The conformance fixtures

The fixtures are email files with really signed envelopes, and a list of cases that says what each one must produce. The keys are published test keys and control nothing.

  • cases.json: the nineteen cases, the test keys, and the canonical form of the four envelopes of the thread. cards.json: the test name cards.
  • 01-request.eml, 02-respond-input.eml, 03-request-answer.eml and 04-respond-done.eml: a four-email thread, each with a human part generated from its envelope.
  • 05-forwarded.eml, 06-stale.eml, 07-tampered.eml: refused silently.
  • 08-hint-mismatch.eml: headers that disagree with the envelope, which the receiver ignores.
  • 09-file-digest.eml: a file that does not match its digest.
  • 10-two-envelopes.eml, 11-auto-reply.eml, 12-stranger.eml: never handed to the agent.
  • 13-reencoded.eml: the envelope re-encoded and re-laid out, which must still verify.
  • 14-bounce.eml: a bounce for the request.
  • 15-bridged-plain.eml: plain email from a person, for a bridge.
  • 16-text-mismatch.eml: a human part that disagrees with its envelope. The agent acts on the envelope; software that shows the text to a person warns.
  • 17-forged.eml: a forgery whose signature, sender and text all fail. The agent refuses it; software that shows it to a person shows that it failed.

The carrier test

A provider passes when it carries 01-request.eml from one of its addresses to another, and the receiving side recovers an envelope whose canonical form equals the one in cases.json, an agenda.txt whose SHA-256 equals the one listed there, and a text part whose digest equals the one the envelope signs. The sending side may rebuild the email through the provider's own interface, as long as it attaches the envelope and the file unchanged and leaves the text unchanged.

Against an implementation

The Agent Emailing Server runs every case twice, against its library and against a running server, with npm run conformance. Get started says how to run the cases against your own.

The reference checker

check-fixtures.mjs is a small reference receiver. Download the conformance folder, with lib.mjs and mail.mjs beside it, and run it with Node.js 20 or later. It needs nothing else installed.

node conformance/check-fixtures.mjs
# pass  e01  01-request.eml
# ...
# all 19 cases pass
