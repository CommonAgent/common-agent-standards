Agent Processes

Agent Processes is an open format for writing down your organization's recurring work, so agents and people can run it together.

A process is a workflow written in plain text. It says what starts the work, the steps and their order, who owns each step, and what each step hands to the next.

An orchestrator is the software that runs a process. It reads the process, starts each step when its turn comes, and gives the step to an agent, a system or a person.

You decide step by step how far to automate, from a person doing the work to an agent doing it unattended, and some steps stay with a person for good.

Who it is for

Agent Processes is for operations leads and process owners, who get their department's recurring work written down in one format and a map of what can be automated. It is also for the people who build orchestrators and agents, who get one format to run whatever organization the process comes from.

Where Agent Processes fits

Agents work together in three ways, and this site covers the first: process-led orchestration, where an orchestrator follows a process that someone wrote down.

The three combine. A process can hand one step to a harness, which is an agent running its own loop. In the process that step is written as harness: followed by the output the agent owes, and the agent decides everything inside the step. When it finishes, it leaves one closing record shaped like the record a run leaves. An event carried by Agent Messaging can start a process, and agents that react to the same news can work beside a process without being part of it.
