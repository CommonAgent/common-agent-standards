What goes where

When something new needs writing down, four questions say whether it belongs in the process, in an extension, in whatever starts runs, or in the catalog.

A process document is the one place that says how the work is done. That only stays true if everything that changes the work goes into it, and everything else stays out. Ask the four questions in order and stop at the first one that answers yes.

  1. Does it change the work?

    Who does a step, the order of the steps, which steps a person must sign, where the work goes back, what passes between steps, what a run is handed and what a run leaves behind. Anything that changes one of these goes in the process document, where its owner can see it, version it and sign it.

    Goes in: the process document

  2. Would a person running it from the page need it?

    If yes, it goes in the process document too. If only software needs it, and it is the same for every run, it goes in an extension: an optional part with its own published definition, which a runtime that does not know it simply ignores.

    Goes in: an extension

  3. Is it the same for every run?

    If it changes from one run to the next, it is not part of the process. It is something a run is handed. Saved answers and saved settings for common uses belong to whatever starts runs.

    Goes in: whatever starts runs

  4. Is it about finding or showing the process?

    Then it belongs in the catalog. The catalog copies every field it shows from the process document, so a field it needs and the document lacks is added to the document's header.

    Goes in: the catalog, copied from the header

A test: what a test run is handed, how its approvals are answered, and what must be true at the endBeside the process: a test case (section 21)3. It differs from one test to the next.
A finished example of what a run producedThe catalog, copied from example:4. It helps a reader choose the process, not run it.

The first question is the one that matters. Calling something a setting, a feature or an extension does not move it out of the process if it changes the work. A setting that skips an approval is a change to the process, and it belongs where the owner signs.
