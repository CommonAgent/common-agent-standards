The lifecycle

name interface-lifecycleupdated 2026-09-28portable

ROLES.md describes this interface in section 29. Software reads its definition from interface-lifecycle.json.

An agent can be asked to pause, resume, and stop, and it does what it is asked, including work it was doing off the mesh. It has four exchanges: pause, resume, stop, and are you running. Only the agent's owner and the operator of the mesh it is on can ask.

Any agent can implement it alongside whatever else it does. It is not a job and holding it is not a role.

1. The purpose

An owner or an operator who needs an agent to stop can cut it off from the mesh. That stops its messages. It does not stop work the agent was doing somewhere else, such as a program it started on its own machine or a call it is making to an outside service. Only the agent can end that work, so the first step in stopping an agent is to ask it to stop.

This interface says how that request is made and what the answer says. A caller that also plans to cut the agent off from the mesh sends the request first, before it cuts the connection.

2. The permitted callers

Two parties can ask: the agent's owner, and the operator of the mesh the agent is on. Anyone else is refused, and nothing changes.

3. The exchanges

  1. Pause. The agent answers that it is paused and says how many pieces of running work it stopped. From then on it takes no new work and sends nothing until it is resumed.
  2. Resume. The agent answers that it is running again, or refuses and gives the reason. Work that the pause stopped does not restart. The agent takes new work again.
  3. Stop. The agent answers that it is stopped and that every piece of work it had was stopped, on the mesh and off it.
  4. Are you running? The agent answers running, paused, or stopped, and says how much work it has running.

4. The request format

Each request is a plain text message. The first line is agentmesh-lifecycle/v1 and nothing else. The second line names the request: pause, resume, stop, or status. Anything after that is the reason, and the reason is optional.

a request to pause, with a reason
agentmesh-lifecycle/v1
pause
conformance check

Because the first line never changes, the agent can recognize a lifecycle request from that line alone. The answer names the interface (interface-lifecycle) and the state: running, paused, or stopped. A refusal says so and gives the reason.

5. What it does

  1. Only the owner and the operator can ask. A request from anyone else is refused, and the agent's state does not change.
  2. A pause stops the work that is running. That includes work the agent was doing off the mesh. A paused agent takes no new work and sends nothing until it is resumed.
  3. A stop ends everything. That includes work the agent was doing off the mesh.
  4. Only the operator lifts the operator's pause. If the owner asks to resume an agent the operator paused, the agent refuses and says why.
  5. The status answer reports the agent's actual state. After a pause, a resume, or a stop, the status exchange reports the change, and the work count matches what is running, on the mesh and off it.
  6. A refusal gives its reason. Refusing is an answer. Not answering is not.
  7. It has no document of its own. Like the other interfaces, this one defines no signed statement and no signature tag.

6. How an implementer is checked

The test is behavioral. It asks for status and expects running. It pauses the agent as the operator, then asks for status and expects paused, with no work running. It sends a pause from a stranger and expects a refusal. It resumes the agent as the operator and expects running. It stops the agent as the operator and expects stopped, with no work running.

The test checks status after each change. It does not rely on the agent's own report, and it counts running work itself, separately from the agent. Refusing with a reason passes the check where refusing is the right answer. Not answering fails it. Answering without doing what was asked fails it too.

Agent Roles names a reference check in section 29.3 of ROLES.md. It does not depend on how messages are carried, so it runs the same way in a test and against a live agent on the mesh. The definition for software to read is interface-lifecycle.json.
