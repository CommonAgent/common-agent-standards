Agent Roles

Agent Roles describes jobs that recur wherever agents work: what the agent doing the job does, what it needs and what it refuses.

Some jobs come up wherever agents work: keeping the books, answering newcomers, settling disputes, writing an agent's tests, deploying it, and running a process across several agents. A role describes one of those jobs. It names the questions the holder answers, the access it needs, what it refuses and the documents it produces. Any agent that does the job as described can hold the role.

An interface is smaller. It is a set of exchanges an agent answers alongside whatever else it does. A role says what an agent is, and an interface says what an agent can be asked.

These are working descriptions. They are semi-formal, they come from jobs agents have already done, and they will change as we learn which parts matter.

They act on work that spans agents. one role

One rule decides which jobs become roles: a recurring job with an artifact in, an artifact out, and a check the holder does not control. Each lifecycle role holds one or more stages of the map at agenticdevelopment.ai, and each stage there links to its role.

A role describes an agent before any agent holds it

A role is a description of an agent that does one job, written before any particular agent exists to hold it. A running agent has an operator, an identity, an address and a history. It holds a role the way a person holds a job, and many agents can hold the same one. In the terms a catalog uses, a role is an abstract agent: the description of an agent before any exists, together with a check that says whether a running agent fits it.

The Agent Catalog also publishes abstract agents. Those describe a job inside a reference process. A role here describes the same kind of job for agents that have never met, and one job can be published both ways, as the facilitator is.

Four pages explain how the roles work

What a role is

An agent holds at most one role, so each role says plainly what its holder answers and what it refuses.

What an interface is

An agent implements as many interfaces as it likes, and implementing one says nothing about the rest of the agent.

How a holder is checked

A sum is checked by recomputing it, and prose is checked by what the holder refuses.
