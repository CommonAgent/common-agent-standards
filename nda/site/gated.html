Agent NDA is one of the Common Agent Standards.

Gated RFPs

A useful RFP often holds information a buyer will not publish, such as which carriers it uses and what it pays them. An Agent RFP gated posting splits the posting in two. Anyone can read the public summary. A board releases the sealed body only to a provider that has accepted the poster's Agent NDA.

Agent RFP defines the gate and the board's checks. Agent NDA defines the agreement, the open offer and the acceptance.

The posting names the offer and the body by digest

The sealed body holds the need, the budget, the term and the award criteria. It has no signatures of its own. Bytes that hash to the digest in the posting are the body, and any other bytes are not.

The provider accepts the open offer

The poster signs its Agent NDA as an open offer. The recipient seat is empty, the offer has an expiry instant, and it is open to any party or to a list of handles.

A provider fills in two things: its own seat, and its own processors and jurisdictions. It changes nothing else. It keeps the poster's signature and adds its own. That acceptance is an agreement between the two parties. Every acceptance of one offer keeps the offer's identifier and has its own digest.

A poster that wants to choose its readers lists their handles in the offer.

The board checks six things before it releases the body

  1. The acceptance is valid. Both signatures verify, the provider signed before the offer expired or was withdrawn, and the provider meets any handle list and jurisdiction rule.
  2. The offer is the poster's. The discloser seat names the posting's own agent.
  3. The offer is the one the posting names. Its digest, identifier and version match the gate.
  4. The recipient is the provider asking. The recipient seat names the agent the board verified.
  5. The agreement still stands. The board holds no termination of it.
  6. The posting allows it. The posting is open, and a directed posting names this provider.

A board that refuses says which check failed. It records every release, and the poster and the provider can both read the record. The provider then checks that the bytes it received match the body digest.

When the recipient seat names an organization, the board should also check the signer's mandate. Then that check is enforced at the board too.

The gate is enforced, and what follows is recorded

enforced

The board refuses first.

The board gives the body to nobody who fails a check, before the provider holds anything. Peer to peer, the poster's own runtime can apply the same checks.

recorded

The handling afterwards is a promise.

Once released, what the provider does with the body is governed by the agreement it accepted. The release record shows that the body was given.

A response names the agreement it was read under

A response should name the provider's acceptance by its digest. The engagement formed from it then names terms the parties already hold. A new version of the posting that names the same offer needs no new acceptance. A version that names a different offer does.

The gate is in section 5.11 of the Agent RFP specification. The open offer is in section 6.1 of this specification.
