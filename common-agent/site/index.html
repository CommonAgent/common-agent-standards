A standard for agents

The Common Agent Specification

The Common Agent Specification defines what an agent is, in terms anyone can check. An agent holds a key that signs. It answers a small set of questions for anyone who asks, and it declares its standing facts in one signed document. It refuses what it does not do with a typed answer, and it collects signed records of what others have checked about it.

The five questions every agent answers
  1. Who are you?
  2. What do you do?
  3. How are you used?
  4. On what terms?
  5. What do you refuse?

Each answer comes from bytes the operator declared and signed. The agent's model is never asked to produce them, so a program can check every answer against its source (Section 4.3).

Three columns

Every fact about an agent comes from one of three places

The specification sorts what can be said about an agent by how a reader checks it, and it keeps the three kinds apart. A reader who knows which column a fact came from knows how far to trust it.

  1. What it answers

    Behavior that a program can test by asking. The exchanges every agent serves and its answers to the five questions belong here.

    A reader checks these by asking the agent.

  2. What it declares

    Standing facts the operator writes once, in the Agent Descriptor: what the agent does, what each offering takes and returns, what it refuses, and what it needs to run.

    A reader checks the format and the signature, and takes the content as the operator's word.

  3. What others attest

    Signed records issued by someone other than the operator about something that happened, such as a build, a deployment or an evaluation.

    A reader checks the issuer's signature and weighs the issuer.

The floor

What every agent must do

Section 4 is the floor. An agent meets every clause in it, and there is no partial floor. On a conforming deployment, calling something an agent means it meets these clauses, and anyone can check that in seconds.

  1. It holds exactly one Ed25519 key, and the public key is its identifier. Section 4.1
  2. It says what it is to anyone who asks, before any relationship exists. Section 4.2
  3. It answers the five questions from its signed declarations. Section 4.3
  4. It keeps an entryway where a stranger may read, and nothing a stranger sends reaches its model, tools or memory. Section 4.4
  5. It implements the four inbound handlers of the agent surface. Section 4.5
  6. It refuses work outside its declared offerings at the boundary, before anything that thinks sees the request. Section 4.6
  7. Every refusal is typed and names its reason. Section 4.7
  8. It enforces the inbound protections before its model sees anything. Section 4.8

The AgentDoc

An AgentDoc is assembled from the agent's Descriptor

The Descriptor is the document the operator writes. The AgentDoc gathers the Descriptor and the signed records others hold about the agent into one document that a program can act on and a person can read, and every part of it says where it came from. Nobody writes an AgentDoc by hand, so it can hold no fact that is missing from its sources.

The AgentDoc is Section 9 of this specification. Its tools, examples and a rendering of that chapter are at agentdoc.net.

Bindings

It works on any network

The specification names no transport. A binding connects an agent to a network: it carries identity, delivery, registration and discovery, and it spells the floor's exchanges in that network's own verbs. An agent that conforms on one binding conforms on any. Agent Messaging is the reference binding (Section 11).

The specification leaves the model, the harness and the way an agent thinks to the people who build it. Conformance means the obligations are met. Whether the work is good is a question for evaluation and reputation, and the specification defines the signed records those produce.
