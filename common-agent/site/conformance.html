Conformance

Checking an agent against the specification

Conformance to the Common Agent Specification is checked by programs. Each check passes or fails on its own, and none of them adds up to a score.

Section 14

What the specification says about conformance

This is the text of Section 14, reproduced from the specification.

The floor is checked mechanically, and a conforming deployment ships the checker: a program that asks Section 4's exchanges of an agent and treats silence as failure, because absence of an error is not evidence of permission. The interview of Section 4.3 is the template. Descriptor checking is Section 6.8's; AgentDoc checking is Section 9.10's. Attribute claims are checked by fetching their artifacts. Behavioral conformance to interfaces and roles is the evaluator's territory, and its verdicts are Section 8.4 records.

Byte-exact obligations are pinned by conformance fixtures, under the family's fixture doctrine: the fixture is the authority, and when an implementation disagrees with it, the implementation is what changes; every case is checkable without a network or a clock, cases whose verdict depends on time carrying their own now; and a fixture contains cases that MUST be accepted as well as cases that MUST be refused, because a fixture of refusals alone is passed by an implementation that refuses everything. Fixture identities are test vectors and control nothing.

Nothing in this section produces a score.

The checks

One mechanical check for each kind of claim

Each chapter that defines a document or an exchange also says how a program checks it. None of these checks asks whether the agent is any good. That question belongs to an evaluator, whose verdict is a signed record of its own (Section 8.4).

Fixtures

Fixtures pin the byte-exact parts

A fixture is a file of test cases that an implementation must agree with. When an implementation disagrees with a fixture, the implementation is what changes. Every case can be checked without a network or a clock, and each fixture holds cases that must be accepted beside cases that must be refused.

  • Trials (Section 7.7, with the trial scope of the allowance in Section 7.5 and the refusals of Section 4.7). The fixture says which trial declarations a registry refuses, the order of admission and its first-failure answer, the fields of a TRIAL_REFUSED refusal, what a node measures at admission, and that only admitted trials are counted. It is published as conformance/trial.json in the specification's repository, and the Agent Messaging Server repository carries the same cases.

A binding pins the byte-level constants this specification leaves symbolic, such as fence text and freshness windows, in its own conformance fixtures. The fixtures for Agent Messaging are described at agentmessaging.ai.
