Agent Messaging is one of the Common Agent Standards. The reference implementation is the Agent Messaging Server.

MCP Events and Agent Messaging

MCP Events lets an MCP client subscribe to events in an upstream system. Agent Messaging is a transport between agents, with inboxes, publish and subscribe, and presence.

Use MCP Events when an agent needs to hear about changes in one system it already reaches through an MCP server, such as a new ticket or an updated file. Use Agent Messaging when agents need to reach each other: to leave a message for an agent that is offline, to publish to a group of subscribers, to share files or a room, or to connect agents that sit behind home or office firewalls.

Who publishes, who receives The server publishes; each matching subscription gets the event Any agent publishes; every matching subscriber receives it

How a subscription works Poll, a push stream, or a webhook with a lifetime A broker subscription, durable or ephemeral, pushed to the agent
Delivery guarantees At least once with a durable upstream; dedupe by eventId At least once, in order per subject; dedupe by sender and id
Where events are stored No store required; replay draws on the upstream's history In the broker; up to 24 hours in three replicas on NATS
After the receiver restarts Resumes from its stored cursor, where the event type supports replay Its durable subscription delivers what it missed
After the server or broker restarts Emit-only events are lost; replayable types recover by cursor Stored events stay in replicated durable streams
A message for one agent that is offline Not supported Held in its inbox for up to 7 days
Files Not supported Inline or by reference; above the 1 MB limit, by signed link
Rooms: a shared conversation, record and files Not supported Rooms extension: members, a shared record and a drive
Who opens the connection The client for poll and push; the server for webhooks Each agent's node opens one outbound connection
Behind NAT or a home firewall Poll and push work; a webhook needs a public HTTPS address Works; agents need no public address or inbound port
Signing HMAC on webhook deliveries; Ed25519 optional Every event signed with the publisher's Ed25519 key
Who may subscribe The server checks the principal; revoked access ends the subscription The broker enforces each node's subject permissions
Payload schema A JSON Schema for each event type Not supported
Filtering Subscription arguments that the event type defines Subject patterns with * and > wildcards
Transport Streamable HTTP or stdio; webhooks over HTTPS A broker binding: NATS JetStream or RabbitMQ
