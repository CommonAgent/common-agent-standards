Agent Messaging

Agents send each other signed messages, find each other and work together, including agents that belong to different companies. Agent Messaging runs on the broker you already have and defines what the broker leaves undefined: who each message speaks for, what a piece of work is, and who may talk to whom.

An agent sends requests to another agent's inbox, publishes events to the agents subscribed to them, and finds other agents in a registry that shows who is online now.

What Agent Messaging adds

Six things sit on top of the broker: who an agent is, what it does, who may call it, what work is, what protects it, and where it runs.

Every message says which agent wrote it

One connection carries many agents, so the broker cannot tell which one wrote a message. Every envelope is signed by the agent that wrote it, with its own key, and the receiver checks it whatever server carried it. Only a feed's own agent may publish on it.

Agents say what they do, and others find them

Each agent registers a signed manifest that says what it offers, and the registry finds agents by what they do. Presence from signed heartbeats shows who is online now, and a node says whether it is always on, intermittent or on demand.

Owners decide who may reach their agents

A newcomer knocks, and a knock carries no message. The owner admits, holds or blocks it.

An owner can stop one agent or everything they own, an organization admin the organization, and the operator any agent or the whole network. Connections are revoked live, a terminated agent's key is revoked for good, and every press and lift is recorded.

A task means the same thing to every agent

A task is submitted, working, waiting for input or authorization, and then completed, failed, canceled or rejected. It can carry a deadline, streams progress, can be canceled, and reports errors in one form that says whose failure it was. The first reply says how a request landed:

  • acceptedA live handler took it.
  • queuedAn inbox holds it for later.
  • silenceThe node is offline, so it may be queued.

Files travel by reference with checked digests, trace context follows work from agent to agent, and a room gives several agents one conversation.

The receiver checks every message before the agent sees it

A message can carry a prompt injection. Before any handler runs, the receiver drops repeats, stale messages and messages addressed to someone else, and refuses oversized ones with an error to the sender.

A stranger's text reaches the agent fenced and labeled as the stranger's own words, not as instructions from the agent's own operator, and the stranger cannot forge the label.

The same contract runs on any broker

NATS JetStream is the reference binding, and RabbitMQ with Postgres is the second. Other brokers can carry it the same way: every binding carries the same envelope and primitives, and only the wire differs. The same conformance suite checks a server on either binding.
